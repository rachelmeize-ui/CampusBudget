# 产品与交互说明

## 用户与目标

面向自己管理生活费的大学生，帮助回答三个问题：这个月花了多少、主要花在哪里、扣除已知安排后每天还有多少可用金额。

核心任务是低成本记录、理解消费结构和安排预算。产品不推销金融产品，不自动判断某笔消费应该发生与否。

## 核心路径

1. 进入应用，默认在模拟账本中查看结果。
2. 选择一句话记账或手动填写。
3. 核对解析出的金额、日期、分类和固定支出标记，确认保存。
4. 查看总览与分类分析。
5. 设置总预算、固定支出和预留金；回到总览查看每日可用参考。
6. 在账本管理中导出 CSV 或确认删除一笔记录。

## 关键设计选择

| 选择 | 原因 |
| --- | --- |
| 打开即有演示数据 | 访问作品时不用先造数据；与真实个人记录分离 |
| 解析后人工确认 | 规则不能理解所有语义；避免错误金额直接进入账本 |
| 无效日期、多金额不猜测 | 保持用户可控，减少静默写错 |
| 显示提醒依据 | 说明阈值和样本数，便于判断提醒是否有参考意义 |
| 小样本不做异常判断 | 同一分类只有一两笔消费时不形成确定性提示 |
| 历史月份不展示日均额度 | 不把当前日期硬套到历史账本 |
| 删除需选择记录并确认 | 避免通过随手输入 ID 删除不相关记录 |

## 可验证的效果

本轮验证的是功能正确性和交互可用性，包括日期解析、保存前确认、金额精度、跨月预算、数据隔离、页面渲染和屏幕适配。验证不包含真实用户满意度、留存或付费数据。

后续可邀请目标用户完成“记录一笔、设置预算、解释一条提醒”三个任务，记录任务完成率、误操作、理解偏差与耗时，再决定是否需要更复杂的 AI 能力。
