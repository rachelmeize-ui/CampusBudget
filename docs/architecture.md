# 架构与边界

## 分层

`app.py` 负责公共框架、月份选择和账本模式；`views.py` 组织页面；`ui.py` 提供视觉组件；`core.py` 提供可单独测试的规则与计算；`storage.py` 完成数据校验、金额单位转换及 SQLite 事务。

演示连接保存在当前 Streamlit 会话内，使用 SQLite `:memory:`；本地账本使用独立文件。连接不通过全局缓存共享。关闭并新建浏览器会话会生成新的演示账本；本地文件在进程重启后仍保留。

## 输入与存储

一句话输入先解析日期并移除日期片段，再提取唯一金额。遇到多个金额、负数或无效日期时提示用户修改。分类使用关键词，无法确定时归为“其他”；保存前允许修改。

金额统一转成整数分存储，避免直接累计 SQLite 浮点金额。类型、分类、日期和金额在存储层再次验证。批量写入先验证整批数据，再在一个事务中执行。

原版 `data/app.db` 没有复制到新项目。新模式使用 `data/budget.db`，也不支持直接把旧版数据库改名后使用；如需迁移应另行编写并验证迁移工具。

## 公开演示

设置 `CAMPUSBUDGET_PUBLIC_DEMO=1` 时，界面仅提供演示模式。公开部署前必须使用该配置。项目尚无登录、服务端权限管理或多人共享账本能力，不能作为多用户财务 SaaS 使用。

演示状态占用服务器进程内存，重启或会话结束后不保证保留。使用本地账本时应定期导出；CSV 不是包含预算配置的完整数据库备份。

## 异常提醒

按所选月份内的同类消费比较，至少需要 5 笔样本。中位数/MAD 规则对明显偏高的记录提供回看线索，但可能漏报或误报，不能代替用户对消费情境的判断。
