# AI 协作说明

## 初版与本轮迭代

CampusBudget 初版由作者借助 Trae 完成，技术方案包含 Streamlit、Python、SQLite、Plotly 和中位数/MAD 提醒。

本轮由作者提出“优化既有项目的界面并整理为 GitHub 作品”的需求，使用 Codex 辅助检查原代码、重构页面、修复问题、编写测试及项目文档。发布版不是初版当时已经具备的全部成果，面试或简历中应区分初版与后续迭代。

## 人与工具的分工

作者提供原项目和目标，确定继续沿用个人预算场景与 Streamlit 技术路线；AI 辅助把需求落实为代码和可复核的测试、截图。项目的目标、取舍、运行边界和对外描述仍需作者理解并复核。

## 本轮值得解释的例子

### 日期被当成金额

初版首先提取文本中的第一个数字，导致 `2026-05-10 奶茶 15` 被解析成 2026 元。本轮先识别并移除日期，再提取唯一金额；用回归测试验证得到 15 元和正确日期，并在界面中增加确认保存。

### 历史月份的日均额度

初版总是根据当前月份和当天日期计算剩余天数。本轮根据选中月份区分历史、当前与未来，分别显示已结算、包含今天的剩余天数或未来月份完整天数。

### 如何判断生成结果

代码生成后运行逻辑与存储测试，再用 Streamlit AppTest 检查页面和保存前确认行为；随后用浏览器检查桌面和小屏布局。只把实际实现、能复现的行为写入 README，不把预设测试当成真实用户增长或准确率指标。
